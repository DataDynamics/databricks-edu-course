# 02. 행·열·키·SQL로 데이터를 읽습니다

**학습 목표:** 한 행의 의미, 스키마, 키를 이해하고 필터·집계 SQL을 읽습니다.

**선수 지식:** [01장](01-data-engineering.md)의 `paid` 금액 집계 규칙.

## 공통 주문 데이터를 읽습니다

모든 입문 실습은 [orders.csv](../../data/orders.csv)를 사용합니다. 이 예제는 **주문 한 건을 한 카테고리에 대응하는 한 행**으로 단순화했습니다. 실제 주문에 여러 상품이 있으면 주문 상세 단위로 다시 설계해야 합니다.

| order_id | category | amount | status |
| --- | --- | --- | --- |
| 1 | book | 12000 | paid |
| 2 | book | 8000 | paid |
| 3 | food | 15000 | paid |
| 4 | food | 5000 | cancelled |
| 5 | book | 7000 | cancelled |

- **행(row):** 관찰하거나 기록한 한 건입니다. “한 행이 무엇인가”를 grain이라고도 합니다.
- **열(column):** 주문 ID, 카테고리, 금액, 상태 같은 속성입니다.
- **스키마(schema):** 열 이름과 자료형 등 구조에 관한 약속입니다. 여기서는 금액을 정수로 해석합니다.
- **키(key):** 행을 식별하는 값입니다. 이번 스냅샷에서 `order_id`는 중복되지 않아야 합니다.

CSV 파일에는 `12000`이라는 문자가 들어 있습니다. Python에서 읽을 때 숫자로 변환하지 않으면 덧셈 대신 문자열 연결이 일어날 수 있습니다. 파일이 있다고 자료형·중복 규칙이 자동으로 보장되는 것은 아닙니다.

## SQL은 표에서 원하는 결과를 표현합니다

아래는 **읽는 법을 배우는 예시**입니다. 아직 `orders` 테이블이 없으므로 바로 실행하지 않습니다. 07장 실습에서 같은 데이터를 임시 뷰로 만들고 실행합니다.

```sql
SELECT category, SUM(amount) AS total_amount
FROM orders
WHERE status = 'paid'
GROUP BY category
ORDER BY category;
```

| 구문 | 읽는 방법 |
| --- | --- |
| `FROM orders` | 주문 데이터를 대상으로 |
| `WHERE status = 'paid'` | 결제 완료 행만 골라 |
| `GROUP BY category` | 카테고리별로 묶고 |
| `SUM(amount)` | 금액을 합산하여 |
| `AS total_amount` | 결과 열 이름을 붙이고 |
| `ORDER BY category` | 카테고리 순으로 표시합니다. |

이 표는 의미를 이해하는 순서입니다. 실제 엔진의 물리 실행 순서까지 고정하는 것은 아닙니다. `ORDER BY` 없이 조회한 행의 표시 순서에는 의존하지 않습니다.

## 손으로 정답을 만듭니다

`paid`인 주문은 1·2·3번입니다. `book = 12000 + 8000 = 20000`, `food = 15000`입니다. 전체 합계는 35,000원입니다.

주문 4·5번은 정상적인 취소 상태이므로 데이터 오류가 아닙니다. 데이터를 보관하되 이번 지표에서만 제외합니다. 상태나 금액이 빠진 값은 `NULL` 또는 결측값으로 다루며, 0과 같은 뜻으로 처리하지 않습니다.

## 확인 문제

1. 주문 1번이 파일에 두 번 들어오면 결과에 어떤 영향이 있나요?
2. 날짜 열이 없는데 일별 금액을 구할 수 있나요?
3. `cancelled`인 두 행은 원본에서 지워야 하나요?

<details>
<summary>해설</summary>

1. 그대로 합산하면 book이 32,000원으로 부풀어 오릅니다. 키 중복을 먼저 확인해야 합니다.
2. 날짜를 알 수 없으므로 계산할 수 없습니다. 필요한 날짜와 시간대 정의를 원본에 추가해야 합니다.
3. 아닙니다. 취소 분석에는 필요한 행입니다. 이번 집계의 필터로 제외합니다.
