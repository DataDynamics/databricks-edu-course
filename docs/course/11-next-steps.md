# 11. 운영 관점으로 복습하고 다음 단계를 고릅니다

**학습 목표:** 전체 흐름을 자기 말로 설명하고, 입문 실습과 운영 시스템의 차이를 구분합니다.

**선수 지식:** [01–10장](../../README.md). 실제 실행하지 않은 실습은 미실행으로 표시합니다.

## 하나의 흐름으로 다시 설명합니다

```text
업무 질문: 어떤 금액을 합산할 것인가?
    ↓
데이터 정의: 한 행·키·자료형·상태는 무엇인가?
    ↓
저장과 계산: 파일을 어디에 두고 어떤 엔진으로 처리하는가?
    ↓
플랫폼과 관리: 누가 어떤 컴퓨트와 이름·권한으로 접근하는가?
    ↓
파이프라인: 원본 → 검증된 상세 → 목적별 집계
    ↓
활용과 운영: 누가 쓰고, 어떻게 갱신·검증·복구하는가?
```

이 흐름에서 Python·Spark·Delta Lake·Unity Catalog·Databricks의 위치를 말할 수 있다면 도구를 서로 대체재로 혼동하지 않고 다음 내용을 배울 준비가 된 것입니다.

## 지금 만든 것과 운영 시스템

| 주제 | 이번 실습 | 운영하려면 추가할 것 |
| --- | --- | --- |
| 입력 | 고정된 5행 스냅샷 | 실제 원본 연결, 갱신 주기, 변경·삭제 처리 |
| 실행 | 사람이 셀을 순서대로 실행 | 작업 의존성, 예약, 실행 주체, 실패 알림 |
| 품질 | 키·값·정답 확인 | 업무별 품질 기준, 오류 격리, 관찰 지표 |
| 재처리 | 전체 스냅샷 교체 | 증분 처리, 처리 범위, 복구·재실행 정책 |
| 공유 | 개인 연습 스키마 | 개발/운영 분리, 그룹별 권한, 변경 검토 |
| 비용 | 작은 입력·짧은 실행 | 사용량 관찰, 실행 주기·자원·보관 기간 관리 |

**배치**는 일정 범위의 데이터를 묶어 처리하고, **스트리밍**은 계속 들어오는 데이터를 지속적으로 처리합니다. 매일 파일을 처리하는 배치도 좋은 출발점입니다. 실시간 요구가 있을 때 지연 시간·중복·늦게 도착하는 데이터 문제를 함께 확장합니다.

## 종합 확인 문제

1. “S3에 올리면 분산 처리, PySpark를 쓰면 모든 Python 코드가 분산 실행된다”는 설명을 고쳐 보세요.
2. 합계가 두 배가 되었다면 컴퓨트를 키우기 전에 무엇을 확인하나요?
3. 어제 Gold가 남아 있는데 오늘 검증이 실패했습니다. 이 결과를 최신이라고 제공해도 되나요?
4. 현재 샘플을 일별 지표로 확장하려면 무엇을 먼저 정의해야 하나요?

<details>
<summary>해설</summary>

1. S3는 저장소이고 Spark는 처리 엔진입니다. 일반 Python 코드와 Spark API의 실행 방식은 다릅니다.
2. 중복 입력, 조인으로 늘어난 행, 같은 스냅샷을 추가 저장한 횟수, 키·집계 기준을 확인합니다. 자원 증설은 의미 오류를 고치지 않습니다.
3. 안 됩니다. 성공 여부·데이터 기준 시점·갱신 시각을 구분하고 실패를 알리는 운영 설계가 필요합니다.
4. 주문일/결제일 중 사용할 날짜, 시간대, 취소·환불 반영 기준, 원본의 변경 이력을 정의합니다.

</details>
