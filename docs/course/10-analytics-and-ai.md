# 10. 분석·ML·RAG는 어떤 데이터를 쓸까요?

**학습 목표:** 같은 데이터 기반이 분석·ML·RAG에서 어떻게 쓰이는지 구분합니다.

**선수 지식:** [09장](09-pipeline.md)의 원본·상세·집계 단계. 이 장은 개념 학습이며 모델·대시보드 구축 실습은 후속 과정입니다.

## Gold의 첫 사용자는 분석가입니다

앞에서 만든 카테고리별 금액 테이블은 SQL로 조회하고 막대그래프 등으로 표현할 수 있습니다. 여기서 **BI**는 보고서와 대시보드를 통해 업무를 이해하고 의사결정하는 활동을 뜻합니다.

분석가에게는 값만 전달하지 않고 정의도 전달해야 합니다. 우리 결과의 설명은 “제공된 스냅샷에서 `paid`인 주문의 카테고리별 원화 금액 합계”입니다. 데이터에 없는 날짜·환불 조건을 덧붙여서는 안 됩니다.

| 활용 | 묻는 질문 | 필요한 데이터 | 현재 샘플로 가능한가요? |
| --- | --- | --- | --- |
| SQL·BI | 어느 카테고리의 결제 완료 금액이 큰가? | 카테고리별 합계 | 가능, book이 큼 |
| 고객 재구매 예측 | 다음 달에 누가 다시 구매할까? | 고객별 과거 행동과 이후 구매 여부 | 불가, 고객·시간 정보 추가 필요 |
| 상품 상담 RAG | 이 상품의 반품 조건은 무엇인가? | 상품 설명·반품 규정 문서와 접근 권한 | 불가, 문서 원본 추가 필요 |

## ML은 과거 데이터로 패턴을 학습합니다

**특성(feature)**은 모델 입력이고, 지도학습의 **레이블(label)**은 맞히려는 정답입니다. **학습(training)**은 데이터로 모델의 규칙을 조정하는 단계이며, **추론(inference)**은 학습한 모델로 새로운 입력의 결과를 구하는 단계입니다.

재구매 예측에서는 기준일 이전 구매 횟수·금액을 특성으로, 이후 재구매 여부를 레이블로 만들 수 있습니다. 이때 예측 당시 알 수 없던 미래 구매 금액을 입력하면 **데이터 누출**입니다. 모델의 숫자가 좋아 보여도 실제 운영에서 쓸 수 없는 평가가 됩니다.

AI가 항상 Gold만 사용하는 것은 아닙니다. 고객별 행동을 만들려면 Silver의 상세 데이터가 필요할 수 있습니다. 모델을 만들기 전에 어떤 시점의 어떤 행을 사용할지 정해야 합니다. [학습·추론과 시점 일치 상세](../data-engineering-lakehouse-ai.md#machine-learning)

## RAG는 관련 문서를 검색해 답변의 근거로 제공합니다

RAG는 질문과 관련된 자료를 찾아 생성형 모델의 입력에 함께 넣는 방식입니다. 문서를 검색에 맞게 나누는 작업을 **청킹**, 의미를 수치 벡터로 표현하는 작업을 **임베딩**이라고 합니다.

```text
준비: 문서 수집 → 텍스트 추출 → 청킹 → 임베딩·검색 인덱스 갱신
응답: 사용자 질문 → 권한에 맞는 근거 검색 → 모델 입력 → 답변과 출처
```

RAG 문서를 갱신하는 것이 곧 모델 자체의 재학습은 아닙니다. 주문 테이블의 권한이 있다고 별도 문서 검색 시스템의 권한까지 자동으로 맞춰지는 것도 아닙니다. 문서 ID·버전·출처·접근 범위를 검색 과정과 함께 관리해야 합니다. [RAG 데이터 흐름 상세](../data-engineering-lakehouse-ai.md#rag)

## 도구 이름을 역할에 붙입니다

Databricks의 SQL·대시보드 도구는 분석 결과 제공, MLflow는 실험·모델 기록, 모델 서빙은 예측 요청 처리와 연결됩니다. 제품 이름을 모두 외우기보다 어떤 입력을 받아 어떤 결과를 내놓는지 구분합니다. [플랫폼의 SQL·BI](../databricks-platform.md#sql-bi), [AI·ML 기능](../databricks-platform.md#ai)

## 확인 문제

1. 현재의 Gold 두 행으로 고객별 재구매 모델을 만들 수 있나요?
2. 반품 정책 문서가 바뀌면 RAG에서 무엇을 갱신해야 하나요?
3. AI를 쓰면 입력 데이터의 오류·권한 문제도 자동으로 해결되나요?

<details>
<summary>해설</summary>

1. 필요한 고객·시간·행동·정답 정보가 없습니다. 원본부터 확장해야 합니다.
2. 해당 문서의 버전과 변경 내용을 반영하여 청크·임베딩·검색 인덱스를 갱신하고 오래된 근거가 남지 않는지 확인합니다. 모델 재학습과 구분합니다.
3. 아닙니다. 정확성·최신성·접근 권한을 데이터 제공 과정에서 관리해야 합니다.

</details>
