# 07. Databricks에서 코드를 실행합니다

**학습 목표:** 워크스페이스·노트북·컴퓨트를 구분하고 PySpark·SQL 결과를 비교합니다.

**선수 지식:** [06장](06-spark.md)의 DataFrame과 Action. 실습에는 Databricks 노트북 실행 환경이 필요합니다.

## Databricks가 연결하는 것

Spark가 계산 엔진이라면 Databricks는 코드를 작성하고, 실행 자원을 연결하고, 데이터와 작업을 관리하는 플랫폼입니다. 처음에는 다음 다섯 역할만 구분하면 됩니다.

| 구성 | 역할 | 이번 학습에서 사용할 때 |
| --- | --- | --- |
| Workspace | 노트북과 파일을 찾는 작업 공간 | 실습 노트북 가져오기 |
| Notebook | 코드·설명·결과를 셀로 묶는 문서 | 순서대로 셀 실행 |
| Compute | 코드를 실제로 실행하는 자원 | Python·Spark 실행 |
| Catalog | 테이블 등 데이터 자산 탐색 | 08–09장에서 이름·저장 결과 확인 |
| Jobs | 작업의 실행 순서·예약·이력 관리 | 입문 이후 자동화로 확장 |

계정은 조직의 사용자·워크스페이스 등을 관리하는 범위이고, 워크스페이스는 실제 작업 공간입니다. 컴퓨트는 저장소와 별개이므로 노트북 파일이 있다고 코드가 실행되는 것은 아닙니다.

## 실행 목적에 맞는 컴퓨트

Python·PySpark 실습에는 이를 실행할 수 있는 **노트북용 컴퓨트**를 연결합니다. SQL 조회 중심 작업은 **SQL Warehouse**를 사용할 수 있습니다. SQL Warehouse는 “DW 데이터 아키텍처”와 이름이 비슷하지만, 여기서는 SQL 실행용 컴퓨트를 뜻합니다.

Serverless는 실행 자원 관리를 플랫폼에 맡기는 방식이고, Classic은 Runtime·자원 등 설정을 더 직접 관리하는 방식입니다. 첫 실습은 조직이 허용한 노트북용 환경을 사용합니다. 모든 계정에서 같은 옵션이 제공된다고 가정하지 않습니다. Serverless에도 API와 데이터 접근 제약이 있으므로, 기존 심화 문서의 JDBC·RDD 예제가 그대로 적용되는지는 별도로 확인합니다. [Serverless 제약](https://docs.databricks.com/aws/en/compute/serverless/limitations)

## 실습 2: PySpark와 SQL로 같은 결과 만들기

[실습 2 안내](../labs/02-pyspark-sql.md)에 따라 [소스 노트북](../../labs/02_pyspark_sql.py)을 가져와 위에서부터 실행합니다.

1. 공통 주문 다섯 건으로 Spark DataFrame을 만듭니다.
2. PySpark로 `paid` 필터와 카테고리별 합계를 표현합니다.
3. 같은 DataFrame을 `orders`라는 **임시 뷰**로 등록합니다.
4. 02장의 SQL을 실행하고 두 결과가 같은지 확인합니다.

임시 뷰는 이 세션에서 SQL로 접근할 이름을 붙인 것입니다. 영구 테이블로 저장한 것은 아니며 세션이 끝나면 다시 만들어야 합니다. 다른 노트북이나 SQL Warehouse에서 같은 이름이 자동으로 보이지 않습니다.

이번 예제는 CSV와 같은 값을 셀에서 직접 정의합니다. PC의 파일 경로와 원격 컴퓨트의 경로를 혼동하지 않고 계산 구조에 집중하기 위해서입니다. 실무 규모의 원본은 Spark가 접근 가능한 저장소·테이블에서 읽습니다.

## 셀 순서도 실행의 일부입니다

아래 셀이 위 셀의 `orders_df`를 사용하므로 중간부터 실행하면 변수가 없다는 오류가 납니다. 컴퓨트를 바꾸거나 세션이 초기화되었다면 처음부터 다시 실행합니다. `show()` 뒤에 `collect()`를 호출하면 다시 계산할 수 있습니다. 결과가 자동으로 캐시된다고 가정하지 않습니다.

## 확인 문제

1. 노트북과 컴퓨트는 무엇이 다른가요?
2. 임시 뷰를 만들면 다른 사람도 영구 테이블처럼 조회할 수 있나요?

<details>
<summary>해설</summary>

1. 노트북은 코드·설명·결과를 담는 문서이고, 컴퓨트는 코드를 실행하는 자원입니다.
2. 아닙니다. 임시 뷰는 해당 세션에 속합니다. 공유할 데이터는 다음 장에서 배우는 카탈로그의 테이블 등으로 관리해야 합니다.

</details>
