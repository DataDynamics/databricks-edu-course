# 공통 주문 데이터

[orders.csv](orders.csv)는 입문 과정 전체에서 사용하는 합성 데이터입니다. 실제 고객 정보는 없습니다. 파일 인코딩은 UTF-8입니다.

## 데이터의 의미

한 행은 **한 시점의 주문 한 건**입니다. 교육을 위해 주문 한 건이 한 카테고리에만 속하도록 단순화했습니다. 주문 이벤트 이력이나 주문 상품 상세 테이블이 아닙니다.

| 열 | 해석할 자료형 | 규칙 |
| --- | --- | --- |
| `order_id` | 정수 | 양수이며 스냅샷 안에서 유일 |
| `category` | 문자열 | 비어 있지 않음 |
| `amount` | 정수 | 원 단위, 0 이상 |
| `status` | 문자열 | `paid` 또는 `cancelled` |

CSV를 Python 표준 라이브러리로 읽으면 값은 문자열입니다. 계산 전에 필요한 값을 정수로 변환합니다. 상태는 샘플에서 소문자로 통일했습니다.

## 공통 질문과 정답

**현재 스냅샷에서 결제 완료 주문의 카테고리별 금액은 얼마인가요?**

| 확인 항목 | 기대값 |
| --- | --- |
| 원본 행 수 / 유일 주문 수 | 5 / 5 |
| 결제 완료 / 취소 | 3 / 2 |
| book 결제 완료 금액 | 20000 |
| food 결제 완료 금액 | 15000 |
| 전체 결제 완료 금액 | 35000 |
| Bronze / Silver / Gold 행 수 | 5 / 5 / 2 |

날짜·시간대·환불·고객·상품 수량이 없으므로 일별 매출, 순매출, 고객별 예측에 필요한 데이터는 충분하지 않습니다.

## 실행 파일과의 관계

- [실습 1](../labs/01_local_sales.py)은 이 CSV를 직접 읽습니다.
- [실습 2](../labs/02_pyspark_sql.py)와 [실습 3](../labs/03_medallion.sql)은 파일 업로드·외부 저장소 권한 없이 시작하도록 같은 값을 셀 안에 정의합니다.
- 샘플을 바꾸면 세 실행 파일의 입력·기대값과 본문 예제도 함께 확인합니다. 고정 정답 검사는 입력을 바꾸면 실패하는 것이 정상입니다.
- 기존 심화 문서에는 별도 문맥의 예제가 있습니다. 저장소 비교 문서의 5행 샘플은 입문 데이터와 일치하도록 맞췄으며, 다른 심화 실습은 각 문서의 입력 정의를 따릅니다.
